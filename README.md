# Linux-school

Проект читает данные из **двух источников**:

1. **Локально** — папка на текущей (рабочей) машине.
2. **Домашний сервер** — по SSH (ключевая аутентификация).

Весь удалённый доступ идёт через штатные `ssh`/`scp`, которые уже есть на
любой Linux-машине, — ничего ставить через `pip` не нужно. Доступом
управляете **вы**: подключение инициируете со своей стороны, по вашему ключу.

## Быстрый старт

```bash
cp .env.example .env     # заполните значения
python3 main.py          # покажет файлы из обоих источников
```

Пока сервер не настроен, локальная часть всё равно работает, а по удалённой
выводится понятная пометка.

## Файлы

| Файл              | Назначение                                        |
|-------------------|---------------------------------------------------|
| `config.py`       | Настройки и описание двух источников, чтение .env |
| `data_sources.py` | `LocalSource` и `RemoteSSHSource`, `load_all()`   |
| `main.py`         | Точка входа — демонстрация чтения из двух мест     |
| `.env.example`    | Шаблон настроек (скопируйте в `.env`)             |

## Настройка SSH к домашнему серверу

> IP сервера вы пока не помните — это нормально. Сначала узнайте его
> (на сервере: `ip a` или `hostname -I`), затем впишите в `.env`.

### 1. Создайте ключ на рабочей машине (если ещё нет)

```bash
ssh-keygen -t ed25519 -C "work-to-home"
# ключ появится в ~/.ssh/id_ed25519 (приватный) и id_ed25519.pub (публичный)
```

### 2. Разрешите вход по этому ключу на домашнем сервере

```bash
ssh-copy-id -p 22 user@IP_СЕРВЕРА
# или вручную: добавьте содержимое id_ed25519.pub в ~/.ssh/authorized_keys на сервере
```

### 3. (Удобно) задайте алиас в `~/.ssh/config`

```
Host home-server
    HostName IP_СЕРВЕРА      # впишете, когда вспомните IP
    Port 22
    User user
    IdentityFile ~/.ssh/id_ed25519
```

Тогда в `.env` достаточно `HOME_SERVER_HOST=home-server`, а подключение —
просто `ssh home-server`.

### 4. Заполните `.env`

```
HOME_SERVER_HOST=IP_СЕРВЕРА        # или home-server, если настроили alias
HOME_SERVER_USER=user
HOME_SERVER_DATA_DIR=/srv/project/data
```

## Как с этим работать над проектом удалённо

- **Зайти на машину и работать:** `ssh home-server` — видите файлы,
  выполняете команды, редактируете. Всё под вашим контролем.
- **Синхронизировать проект:** так как это git-репозиторий, удобнее всего
  `git pull` / `git push` с обеих сторон. Для папок с данными подойдёт
  `rsync -avz ./data/ home-server:/srv/project/data/`.

## Про «чтобы Claude мог видеть и давать команды»

Claude не является постоянно работающим сервисом и не может сам
подключаться к вашим машинам. Чтобы получать помощь с кодом на машине без
Claude Code, рабочий путь — редактировать проект в git-репозитории и
приносить файлы/вывод команд в сессию. Скрытых агентов удалённого
управления этот проект не содержит и содержать не должен.
